# FOC 20kHz 高频控制下 1kHz 波形传输与采样率系统评估报告

## 1. 概述与背景

在 Universal-FOC / MODUS 调试框架中，高频控制中断（`foc_app_HighFrequencyISR()`）运行在 20 kHz（对应 20 kHz PWM 载波与 ADC 采样），负责电流采样、坐标变换、转矩/速度环控制及无感位置观测器（如 SMO / NLFO / HFI）的实时计算。

当高频 ISR 占用了高达 **80% 的 MCU CPU 资源**时，本文针对上位机波形监控（`mwaveform` 模块，4~6 个通道）以 **1 kHz 采样频率发送** 的可行性、算力/带宽开销、芯片架构差异及采样率观察效果进行定量评估与方案设计。

---

## 2. 第一性原理与定量计算 (Quantitative Analysis)

### 2.1 CPU 时间与算力预算

在 20 kHz 高频控制周期下，每个控制周期时间为：
$$T_{\text{ISR}} = \frac{1}{20\,\text{kHz}} = 50\,\mu\text{s}$$

当高频 ISR 占用 80% CPU 资源时：
* **高频 ISR 耗时**：每次中断占据 $40\,\mu\text{s}$。
* **后台空闲切片**：每个周期中断退出后，留给主循环（Background Thread） $10\,\mu\text{s}$。
* **1 ms (1 kHz) 发送时间窗口**：包含 20 个高频 ISR 周期。
* **后台可利用时间**：在 1 ms 窗口内，主循环累计获得 **$200\,\mu\text{s}$ 的纯后台 CPU 执行时间**。

#### 打包开销计算：
每 1 ms 触发一次 4~6 通道数据打包（`mwaveform.Push()` + `pack_data()`）：
* 单次打包在 Cortex-M4 / M4F 架构上仅需 **80 ~ 100 个 CPU cycles**（耗时 $< 0.6\,\mu\text{s}$）。
* **整体 CPU 占用率**：
  $$\text{CPU 占用率} = \frac{100\text{ cycles}}{1\text{ms cycles}} \approx 0.05\% \sim 0.06\%$$
* 该开销仅占主循环后台可用算力（$200\,\mu\text{s}$）的 **小于 0.3%**，算力余量极其充裕。

---

### 2.2 数据吞吐量与物理层传输分析

* **单帧数据包结构**（4~6 通道 16-bit PCM 编码）：
  $$\text{Frame Size} = 2\,\text{B (Header)} + 1\,\text{B (Seq)} + 1\,\text{B (Mask)} + 8\sim 12\,\text{B (Payload)} + 1\,\text{B (Checksum)} \approx 14 \sim 18\,\text{Bytes}$$
* **1 kHz 持续吞吐量需求**：
  $$\text{Data Rate} = 1000\text{ frames/s} \times 18\text{ Bytes/frame} = 18\text{ KB/s} \quad (144\text{ kbps})$$

#### 传输通道接口适配力评估：

| 物理传输介质 | 理论/实测有效带宽 | $18\text{ KB/s}$ 需求占比 | 评估结论 |
| :--- | :--- | :--- | :--- |
| **SEGGER RTT** | 500 KB/s ~ 2.5 MB/s | **$< 5\%$** | 默认推荐，SWD 传输极顺畅，无丢包 |
| **USB CDC (虚拟串口)** | 800 KB/s ~ 1 MB/s | **$< 2.5\%$** | 全速 USB DMA 传输，无压力 |
| **USART + DMA (硬件串口)** | 460800 / 921600 bps | **$< 40\%$** | 配置高波特率 + DMA 发送，CPU 0 占用 |

## 3. 跨芯片微架构对比分析 (AT32F413 vs STM32G431)

针对工程支持的主流 MCU 进行硬件资源与微架构适配评估：

| 芯片型号 | 主频与内核 | 1ms 算力预算 | 架构优势与适配说明 |
| :--- | :--- | :--- | :--- |
| **AT32F413** | 200 MHz Cortex-M4 | 200,000 cycles | 高主频带来极高的后台算力冗余（后台可用 40,000 cycles/ms）。 |
| **STM32G431** | 170 MHz Cortex-M4F | 170,000 cycles | 包含硬件 FPU、CORDIC 和 FMAC，且拥有 10KB CCMRAM。打包数据可排布在 CCMRAM 中，避免与 DMA 争抢 SRAM 总线带宽。 |

## 4. 采样率观察效果与波形对比分析 (1 kHz vs 20 kHz)

在波形绘制和实际调试中，是否需要 20 kHz 原始数据全速推送的对比矩阵：

### 4.1 奈奎斯特采样定理与动态响应

根据奈奎斯特采样定理，1 kHz 采样率的理论上限观察频率为 **500 Hz**。
* **50Hz 基波正弦波**（周期 20ms）：1 kHz 采样下每个周期获取 **20 个采样点**。上位机插值绘制出的波形极其平滑自然。
* **控制环路观察**：速度环/位置环带宽通常在 10Hz~100Hz，1 kHz 采样率能 100% 完整捕捉阶跃响应、PID 调节与角度跟踪曲线。

### 4.2 1 kHz 降采样与 20 kHz 全速对比

| 评估维度 | 1 kHz 降采样发送 (**默认推荐**) | 20 kHz 全速持续发送 |
| :--- | :--- | :--- |
| **观察波形效果** | 20 点/周期 (50Hz正弦波)，流畅光滑 | 400 点/周期，极其密集甚至折叠 |
| **网络与串口带宽** | **18 KB/s (144 kbps)**，占用极低 | **360 KB/s (2.88 Mbps)**，易导致串口暴毙 |
| **上位机 UI 渲染** | 60 FPS 无卡顿，GPU/CPU 占用 $<1\%$ | 上位机绘图线程易卡顿、掉帧、内存飙升 |
| **适用调试场景** | **PID调参、速度/转矩阶跃、无感角度/转速跟踪、长时间在线监控** | **PWM死区纹波分析、单周期开关故障排查、高频注入 (HFI) 调试** |

## 5. 工业级最佳实践方案

推荐采用 **“1 kHz 动态流式在线 + 20 kHz 触发快照 (Snapshot)”** 组合架构：

1. **常规实时监控模式 (1 kHz 在线流)**：
   * 设置分频系数 $N=20$（20 kHz / 20 = 1 kHz）。
   * 持续在线观察 $I_q, I_d, \text{Speed}, \theta$ 等控制量，画面顺畅，对 CPU 与上位机零负担。

2. **微观/故障诊断模式 (20 kHz Snapshot 触发快照)**：
   * 针对 PWM 开关纹波或过流保护瞬间分析：
   * 在 MCU 内部分配一小块 RAM 缓冲区（如 200 个点，对应 10ms 长度）。
   * 触发故障或点击“单次抓取”后，ISR 以 20 kHz 全速将原始数据填入 RAM 缓冲区。
   * 填满后由主循环在后台离线传输至上位机绘制（即数字示波器的 **Single 触发模式**）。
