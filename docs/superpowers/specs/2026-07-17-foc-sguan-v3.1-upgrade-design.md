# Universal FOC v3.1 算法升级设计

日期：2026-07-17  
参考实现：`reference/SguanFOC_Library` v3.1.0  
验证目标：AT32F413，浮点与 Q16.15 双配置

## 1. 目标

在不照搬 SguanFOC 全局框架的前提下，吸收 v3.1.0 中可通用化的
FOC 算法，完善当前 `foc` 库尚未实现的控制器、观测器、调制、优化
和辨识能力。

更新后的库必须满足：

- 面向对象的 C 语言设计，`motor_handle_t` 表示一台独立电机。
- 支持同时静态实例化和运行多台电机。
- 高内聚、低耦合，算法、调度、硬件和应用单向依赖。
- 浮点和定点共用算法结构与数值语义。
- 默认定点格式为使用 `int32_t` 存储的 Q16.15。
- 核心库与 Cortex-M、RISC-V 及具体芯片无关。
- 不使用动态内存，不在高速控制环中输出日志。
- 以 AT32F413 双数值配置编译和主机 C 单元测试作为本轮验收。
- 不把电机实机闭环效果列入本轮验收。

## 2. 非目标

- 不直接复制 SguanFOC 的全局大结构体、宏驱动主循环和 `UserData_*`
  硬件适配方式。
- 不移植 `Sguan_printf`；继续使用 MODUS mdebug、mshell、waveform 和
  USB CDC。
- 不要求同一固件同时包含浮点和定点两套实现。
- 不承诺未经硬件验证的 HFI、SMO、NLFO、NSD 和参数辨识实机性能。
- 不为每个数学函数建立虚表或运行期分派。

## 3. 分层架构

依赖关系如下：

```text
foc/app
   |
   v
foc/motor                 单电机聚合根、状态机、高低频调度
   |-- control            PID/LADRC/SMC/STA/DOB/前馈/滤波
   |-- observer           Hall/HFI/SMO/NLFO/PLL/观测器融合
   |-- modulation         SVPWM/SPWM
   |-- optimization       MTPA/弱磁/补偿/齿槽/辨识
   |-- math               数值后端、角度、矢量、坐标变换
   `-- hal                与芯片无关的硬件能力接口
                              ^
peripheral/at32f413           MDI 到 FOC HAL 的实例适配
```

核心规则：

- `foc/` 不包含 CMSIS、AT32、STM32 或 RISC-V 厂商头文件。
- 算法模块只接收自己的状态、参数、输入和输出，不访问完整
  `motor_handle_t`，也不直接操作 ADC、PWM 或 MDI。
- `motor` 层组织控制链和状态迁移，不重复实现算法。
- `app` 只负责示例、命令和调试，不承载控制算法。
- SguanFOC 参考目录保持只读；派生算法文件保留其 MIT 版权说明。

## 4. 多电机对象模型

`motor_handle_t` 是一台电机的聚合根，保存：

- 电机基值、物理参数和预计算离散系数。
- 实时电流、电压、角度、速度、运行状态和故障位。
- 当前控制器、调制器、传感器、观测器和融合器的接口及上下文。
- 当前运行模式和观测器切换状态。

所有可变状态都属于实例。算法文件不得使用可写全局或静态状态；
只读查表和不可变操作表可以由多个实例共享。

HAL 回调必须包含上下文：

```c
typedef struct {
    void *pContext;
    void (*fnSetDuty)(void *pContext,
                      foc_scalar_t qU,
                      foc_scalar_t qV,
                      foc_scalar_t qW);
    void (*fnEnable)(void *pContext, bool bEnable);
    void (*fnEmergencyStop)(void *pContext);
} foc_pwm_if_t;
```

ADC、编码器、Hall 和其他硬件接口采用相同模式。AT32F413 MDI 适配器
为每台电机保存独立设备引用，不能依赖唯一的 `HW.ptMotorU`。

算法上下文由应用静态分配并注入，不使用堆。`motor_handle_t` 不内嵌
所有可选高级算法的大型状态，从而使每台电机只消耗实际启用组件的
RAM。

## 5. 数值模型

### 5.1 统一标幺语义

高速环中的电流、电压、速度、磁链和控制输出统一使用标幺值：

- 浮点 backend 使用 `float`。
- 定点 backend 使用 `int32_t` 存储 Q16.15。
- 同一输入在两个 backend 中必须产生容差范围内一致的输出。

电阻、电感和磁链等物理参数不直接以 Q16.15 SI 值保存。用户配置
采用明确工程单位，例如 mΩ、µH、mV、mA 和 rpm。初始化阶段计算
标幺值和离散系数，高速环只使用预计算结果。

### 5.2 角度

- 电角度表示一电周期的标幺值 `[0, 1)`。
- `foc_angle_t` 在接口上与普通标量区分。
- 正余弦、`atan2` 和角度环绕统一通过角度 API。
- 机械角、电角、机械速度和电角速度使用不同字段名。
- 极对数换算集中处理，不散落在控制器和观测器中。

### 5.3 M0 和 RV32 效率

通用 64 位乘除不得进入高频路径：

- `foc_mul_pu()` 和 `foc_mac_pu()` 处理范围受限的标幺量，使用 32 位
  运算、移位和饱和。
- `foc_mul_wide()` 只用于初始化、参数换算和低频任务。
- 控制器系数在初始化时分解为适合快速路径的系数和移位。
- 需要扩展动态范围的积分器和观测器状态使用明确的专用格式。
- 编译产物检查高频对象是否意外引用 64 位乘除软件辅助函数。

默认 backend 使用标准 C。Cortex-M DSP/FPU 或 RISC-V M/DSP 扩展仅
作为 `foc/math/port/` 下的可选优化，不能改变算法接口和结果语义。

## 6. 高频数据流

```text
ADC 原始值
 -> HAL 标定与采样
 -> 标幺相电流
 -> Clarke/Park
 -> 电流控制器与补偿
 -> iPark
 -> 调制器
 -> 标幺占空比
 -> HAL PWM
```

观测器读取已计算的 αβ 电流、电压、母线状态和采样周期，不直接读取
ADC，也不直接写 PWM。HFI 注入通过控制链的显式叠加输入完成。

## 7. 组件接口

每个算法采用独立的参数、状态、输入和输出结构，并提供：

```text
Module_Init()
Module_Reset()
Module_Step()
```

初始化负责参数验证和系数预计算。`Step` 不分配内存、不打印日志，
只更新自己的状态和输出。

只有确实需要替换的组件使用接口表：

- 硬件能力。
- 控制器选择。
- 角度和速度观测源。
- 调制器选择。

控制器、调制器和滤波器在初始化或停机状态绑定。运行中动态切换只
用于运行模式及角度/速度来源。

## 8. 观测器切换

支持以下产品所需切换：

- 开环启动到 SMO 或 NLFO。
- HFI 到 SMO 或 NLFO。
- Hall 到 SMO 或 NLFO。

切换条件包括：

- 新观测器输出有效并达到置信度阈值。
- 速度跨过带迟滞的阈值。
- 满足最短稳定时间。
- 在配置窗口内融合角度和速度。
- 角度差超限时取消切换并保留原来源。

PID、LADRC、SMC 和 STA 不支持无条件在线替换。后续若有产品需求，
必须增加状态迁移和无扰切换接口。

## 9. 算法实施阶段

### 阶段一：数值与基础控制

- 双数值 backend、角度和标幺转换。
- Clarke、Park、iPark。
- SVPWM、SPWM、三次谐波注入。
- PID、PLL、LTD。
- 一阶滤波及 Butterworth、Chebyshev、Bessel 二阶滤波。
- 电流和速度前馈。

### 阶段二：多电机控制框架

- 多实例 `motor_handle_t`。
- 实例化 HAL、采样、PWM 和组件上下文。
- 电压开环、电流环、速度环和位置环。
- 高频环、低频环和故障状态机。
- 开环启动到闭环的统一状态接口。
- AT32F413 MDI 多实例适配。

### 阶段三：位置与速度观测

- Hall、SMO、NLFO 和观测器 PLL。
- 开环或 Hall 到 SMO/NLFO 的融合切换。
- 只观察不接管 PWM 的调试模式。

### 阶段四：低速无感与高级控制

- HFI 注入、解调和 HFI 到 SMO/NLFO 切换。
- LADRC、SMC、STA。
- DOB 扰动观测器。

### 阶段五：优化与补偿

- MTPA、弱磁、相位延迟补偿和死区补偿。
- 谐波抑制和抗齿槽转矩。
- 齿槽表由应用提供存储，不固定内嵌到每台电机。

### 阶段六：实验功能

- NSD 转子极性辨识。
- 电机参数辨识。

SguanFOC v3.1.0 README 明确说明这两项存在缺陷。实现必须默认关闭，
头文件和源码注释必须标记“实验性、参考实现存在已知缺陷、未经硬件
验证”。它们只能在停机或专用辨识状态运行，异常时立即关闭 PWM。

## 10. 错误和安全处理

初始化返回明确错误码，包括：

- 空接口或必需回调缺失。
- 基值、采样周期、极对数或参数非法。
- 控制器或观测器配置不完整。
- 定点系数超出可表示范围。
- 运行模式组合不受支持。

每台电机维护独立故障位，包括采样无效、母线异常、持续数值饱和、
观测器失锁、切换失败和硬件故障。严重故障输出零矢量并调用该实例
的 PWM 禁止接口。高速环只记录状态，诊断输出由低频层或应用读取。

## 11. 验证

测试使用 C 和 Makefile，不使用 Python。

主机单元测试覆盖：

- 数学函数和坐标变换已知向量。
- Park/iPark 往返误差。
- SVPWM/SPWM 范围、连续性和限幅。
- 控制器复位、限幅和抗积分饱和。
- 滤波器稳定性和阶跃响应。
- 观测器离线输入、有效性和失锁处理。
- 浮点与 Q16.15 结果一致性。
- 两个电机实例交错执行时的状态隔离。
- 实验性算法的参数边界和安全退出。

AT32F413 分别使用独立目录构建：

```powershell
mingw32-make TARGET_CHIP=at32f413 FOC_NUMERIC=float `
    BUILD_DIR=build/at32f413-float

mingw32-make TARGET_CHIP=at32f413 FOC_NUMERIC=fixed `
    BUILD_DIR=build/at32f413-fixed
```

如果对应工具链存在，则增加 Cortex-M0 和 RISC-V 核心源码编译检查；
否则以严格标准 C 主机编译和厂商头文件依赖扫描验证架构边界。

## 12. 完成标准

- 六个阶段的稳定算法均具有实现、公开接口和单元测试。
- 实验算法默认关闭并具有醒目、准确的已知限制注释。
- 浮点与定点主机测试通过。
- AT32F413 浮点和定点配置均全量编译通过。
- 多电机实例测试证明状态和 HAL 上下文互不串扰。
- 高频定点路径不存在非预期的 64 位乘除辅助调用。
- `foc/` 不依赖任何具体 MCU 或 CPU 架构头文件。
- 原有 FOC 功能通过兼容层或迁移说明保持功能兼容。
