# grblHAL 驱动已知问题

由于当前硬件接口或通信契约尚未最终确定，以下问题暂缓处理。

1. 当前未声明输入流暂停能力。USB CDC 和 UART 尚不支持为自动换刀流程
   保存及恢复输入队列。
2. `hal.delay_ms` 仍使用 perf_counter 进行阻塞延时。不得在 grblHAL 实时
   执行路径中引入较长的驱动层延时。
3. 当前以 USB 设备进入 configured 状态作为连接成功的判断依据，尚未跟踪
   主机 DTR 状态或应用层在线状态。
4. 限位、控制、冷却和探针能力仍属于预留功能，需要等待最终物理接口确认。
   不能仅因为 `docs/cnc_pin_mapping.md` 中存在候选引脚就启用对应能力。
5. 步进驱动器共用一个使能输出，无法单独禁用某一轴，也无法实现逐轴保持
   策略。

仍需完成以下硬件验证：

- 通过 USB CDC 连续发送较长的 G-code，同时高频请求实时状态报告；
- 在 RX 队列已满的情况下验证复位和取消操作；
- 使用逻辑分析仪测量 STEP 脉宽和 DIR 建立时间；
- 验证 `M3/M5` 对 PA6 的控制，并确认所有致命异常路径都会强制关闭 PA6。
